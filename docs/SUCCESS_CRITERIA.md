# 프로젝트 성공 기준 및 절대 보호 규칙 (Success Criteria & Guardrails)

## 1. 한 줄 합격 기준 (One-Line Pass Criterion)
> **"무엇이 되면 이번 작업물이 합격인가?"**
- **요청한 기능이 실제 사이트(화면)에서 에러 없이 정상 작동하고, 기존에 만들어진 기능과 디자인이 단 하나도 깨지지 않으면 합격이다.**

## 2. 절대 건드리거나 임의로 만들면 안 되는 것 (Non-Goals & Protection Rules)
- [x] **기존 기능 변경 금지**: 사용자가 말하기 전에는 기존에 작동하던 버튼, 링크, 데이터 처리, 페이지 이동 등 모든 기존 기능을 절대 건드리지 마세요.
- [x] **기존 디자인 변경 금지**: 사용자가 말하기 전에는 기존 레이아웃, 색상, 폰트, 크기, 간격, CSS 스타일, 문구를 절대 임의로 바꾸지 마세요.
- [x] **요청하지 않은 기능/라이브러리 추가 금지**: 시키지 않은 부가 기능, 팝업, 애니메이션, 외부 패키지를 임의로 추가하지 마세요.
- [x] **허용 범위 외 파일 수정 금지**: `docs/POLARIS_PLAN.md`에 명시한 작업 대상 파일 외에는 어떤 파일도 수정하지 마세요.

## 3. 작업 위험도 분류 및 안전 장치 (Reversibility Guardrails)
- **신규 추가 작업**: 기존 파일과의 충돌을 최소화하여 분리된 컴포넌트/함수로 작성하고 실제 화면 렌더링 확인
- **되돌릴 수 없는 핵심 영역 (결제/계산, 인증/비밀키, 유저 데이터, 기존 핵심 라우팅)**: 수정 전 반드시 백업/테스트를 먼저 세우고, 기존 동작이 그대로 통과하는지 자동 검사로 확인

## 4. 자동 환경 감지 기반 검증 수단 (Auto-Detected Verification)
사용자가 기술 스택을 지정하지 않아도 하네스 훅이 프로젝트 파일(`index.html`, `package.json`, `pyproject.toml` 등)을 자동으로 감지하여 문법 검사·테스트·빌드 무결성을 검증합니다.
